# Website inquiry menu merge

Website Inquiry is always visible and its loaded inquiries show their menu, event fields and notes expanded. Last 5, search, Show All, review status, deletion and Catering To Go's separate controls retain their existing behavior.

Each website inquiry has **Merge into confirmed event**. The dialog loads active confirmed events, suggests exact normalized last-name matches (including names in imported calendar titles), and allows searching and choosing another event. A suggestion never performs a merge. Staff review the existing and replacement menus and check confirmation before submitting. Changing the selected event or search resets confirmation.

The merge replaces buffet/package selections, food extras, dietary/preparation requests, guest count and a supplied food-out time. It fills missing contact fields and retains nonempty confirmed contact details. Booking date, start/end times, location, status, existing custom charges, tax settings, discounts, payments and internal notes stay on the confirmed event. Customer notes are appended without repeated copies. Current backend catalog parsing/calculations validate the saved menu. Issued proposal snapshots are kept; staff create a revised draft and explicitly approve sending afterward. Merging sends no customer email and makes no Stripe call.

The server locks the booking and inquiry, verifies the reviewed inquiry/catalog fingerprint and target version, saves through the existing event service and records the source inquiry with a before-merge audit in its existing payload. Primary inquiry links remain intact; additional menu inquiries resolve to the same event through `menuImportedPlanId`. Confirmed merged inquiries leave the pending list and remain accessible by their original inquiry ID and in event reports. Repeated identical requests do not update twice. An inquiry already merged into another active event cannot be silently reassigned. Editing an open target locally blocks merging until those edits are saved or closed.

An otherwise unused Draft/Tentative planning copy can be archived from the active calendar while retaining its original details and unsent drafts in Reports. Another confirmed/Google-linked event, sent/approved/accepted proposals or checkout/payment history on a source copy blocks consolidation for staff review. The target's payment and historical proposal records are never moved or erased. Failures roll back the transaction.

Validation: `npm run test:event-plans`, `npm run test:event-booking` using a new disposable local `EVENT_TEST_DATABASE_URL` as required by that harness, `npm run test:event-editor-ui` and `npm run test:inquiry-merge-ui`. Browser tests use mocked manager APIs; `AVIATOR_PLAYWRIGHT_MODULE` can identify an installed Playwright module and `EVENT_EDITOR_UI_ORIGIN` can select deployed assets. No real emails or payments are used in tests.
