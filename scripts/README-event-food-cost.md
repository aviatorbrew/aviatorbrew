# Internal event food-cost estimates

Expand an event in Manager → Private Events and open **FOOD COST ESTIMATE**, directly below MENU. The summary shows either an approximate total with food-cost percentage, or a clearly labeled known-cost subtotal and coverage count. Missing costs and unknown production quantities are excluded and explicitly listed. Incomplete estimates never show an overall food margin.

Costs come from the existing authenticated private-event settings record, under `foodCosts`. The client bundle has no built-in business cost amounts. Configure them with **Edit internal food costs**, which opens **Event Settings → Internal food cost estimates**. A cost can be entered per finished pound, full S-22409 pan, half S-22408 pan, whole pizza, event guest or piece. Each entry has an optional source. Blank is unknown; an explicitly entered zero is retained as zero. Earlier manager-supplied estimates can be entered with that source; they are not represented as verified current invoice/recipe costs.

Pan-based costs are prorated by the food’s measured pan fill, or the clearly labeled estimated fill when no measurement is saved. Pizza weight costs include whole-pizza rounding, and pizza-unit costs require known pie counts. Explicit custom food quantities are retained; unknown units are flagged. Billing prices are never used as ingredient costs. The estimate uses current internal settings and production targets; it is an allocation forecast, not a historical supplier invoice or a full-batch purchasing total.

Food revenue is the existing Food-category subtotal less its proportional share of a manager discount, before sales/PFB tax. Room/drink revenue and deposits do not affect food-cost percentage. Food margin, when all foods can be costed, is before labor, unpriced packaging, payment fees and overhead. Internal food costs are excluded from customer proposals, public catalog data and kitchen printouts. Changing costs or pan fills does not modify saved customer selections, quantities, prices, payments or issued proposal snapshots.

Manager settings and event-list APIs require the existing manager authorization and use private/no-store responses. The existing kitchen/food settings screen is extended; there is no new inventory integration or duplicate menu backend.

Validation: `npm run test:event-food-cost`, the disposable-local-database `npm run test:event-booking` harness, and `npm run test:event-food-cost-ui` (mocked APIs, desktop/mobile). Covers incomplete totals, missing quantities, valid zero costs, measured/estimated pan units, pizza rounding, discounts and tax/deposit separation, private settings, live UI refresh, unsaved menu preview, preserved billing and print privacy. No real customer email or payment is used in tests.

## Shared Private Events / Feast update (2026-11-09)

The manager-only **Food cost updates** panel appears in Private Events and Feast. It shows each rate, basis, source/assumption, update date, last supplier check/attempt, unavailable sources and protected overrides. Private Events keeps its existing editor and per-event estimate; Feast adds an internal per-order estimate from the saved production quantities. All rates remain in the existing `private_event_settings.foodCosts` record. The seed is `scripts/data/food-cost-estimates-2026-11-09.json` (server import only, never public catalog data). It includes 97 rough food/portion/supply/allowance rates and preserves any existing entries whose source is not an identified earlier manager estimate.

The supplied raw pork price is $1.35/lb. A **planning assumption** of 60% cooked yield produces $2.25/lb meat; $0.75/lb covers estimated sauce/seasoning/variation, making the internal rate $3 per finished lb. Pork is a protected manual input, never replaced by a public supplier quote. Other recipe allowances are estimates, not verified US Foods invoices or actual kitchen recipes. Earlier mac ($30/10 lb) and meatloaf ($50/10 lb) estimates become $3/lb and $5/lb. The former $15/full-pan wing estimate is replaced by a clearly marked $6/lb cooked bone-in planning estimate. Actual invoice and yield review remains necessary.

Feast converts known weights, fluid volumes and explicit piece counts separately, and never treats raw bird weights as cooked meat. Whole birds/pies/breads/pieces have their own rates. Package sauce/condiment and standard packaging costs are explicitly labeled budget allowances; no new kitchen quantities are invented. Beer inventory supplies selling prices, not production costs, so unknown beer costs remain incomplete. Missing/unrecognized units and missing historical package-serving descriptions suppress an overall percentage. Customer quote snapshots, selling prices, taxes, payment balances, portions, kitchen output and customer documents/emails are unchanged.

### Weekly job

The already-active protected Render Feast follow-up job invokes the cost check too; no extra service, secret, billing plan or cron command is needed. A persisted week gate runs once each **Monday at/after 8 a.m. America/New_York**, using the existing 15-minute cron cadence, with catch-up on the next invocation after downtime. A PostgreSQL advisory lock prevents overlapping checks. Install/refresh endpoints require existing manager authentication; scheduled access uses the existing protected automation endpoint. No customer email is sent.

The current public integration checks five exact CHEF’STORE product pages: cooked breaded chicken, tots, shredded mozzarella, spinach and brisket. The reader verifies primary SKU, purchase pack/weight and positive price; it does not scrape related products, search snippets, historical promotions or conflicting JSON-LD prices. These are public default-location benchmarks, **not Aviator's US Foods account prices**. A real account feed/export integration is not configured.

Twelve cost rates currently map to those ingredients. On the first check, verified supplier prices establish a baseline without altering the approved initial estimates. Later checks apply the documented estimated ingredient cost shares to those rates, keeping other recipe allowances fixed. Missing prices, changed units and price movements beyond 20% of the baseline retain previous costs and are reported for review. Unmapped recipes retain their explicitly labeled estimates. Manager overrides are detected against the last applied rate and protected. The supplier result and up to 52 run summaries are saved under `food_cost_updates`; previous `lastCheckedAt` is retained if every lookup fails. Manual cost editing uses a cost-specific ETag so a stale browser cannot overwrite a later weekly update.

Validation: `FOOD_COST_TEST_DATABASE_URL=postgresql://.../aviator_foodcost_test_* npm run test:food-cost-updates`; `AVIATOR_PLAYWRIGHT_MODULE=... node scripts/test-food-cost-updates-ui.mjs`; existing event-food-cost, event-booking and Feast suites. All write tests use isolated local databases; Stripe/mail are simulated.
